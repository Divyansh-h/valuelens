# ValueLens: SQL Interview Reference Guide

This document catalogs the exact SQL concepts utilized to build the ValueLens data pipeline. As requested, it strictly excludes concepts that were not genuinely utilized in the project (such as `CASE` or `HAVING`, which were intentionally pushed upstream to Pandas for easier dictionary mapping and data cleaning).

For your Mu Sigma interview, use this guide to prove you didn't just "write SQL", but rather that you *architected SQL specifically to solve business problems.*

---

## 1. Common Table Expressions (CTEs)
**Where it was used:** `sql/02_rfm_analysis.sql` and `sql/03_segment_summary.sql`
**Why it was used:** To break down complex, multi-step calculations into readable, modular blocks instead of deeply nested subqueries.
**Business Question:** *"How do we calculate Recency without hardcoding today's date?"*
**Implementation Example:**
```sql
WITH snapshot AS (
    -- Dynamically determines the 'current' day of the dataset
    SELECT DATETIME(MAX(invoicedate), '+1 day') AS snapshot_date
    FROM sales
)
```

## 2. Window Functions (`NTILE`)
**Where it was used:** `sql/02_rfm_analysis.sql`
**Why it was used:** To automatically bucket customers into statistical quintiles/tertiles without hardcoding arbitrary monetary thresholds (which would break if the company grew).
**Business Question:** *"How do we mathematically separate our Top 33% of buyers from our Bottom 33%?"*
**Implementation Example:**
```sql
SELECT 
    customerid,
    -- NTILE automatically ranks and splits the population evenly
    NTILE(5) OVER (ORDER BY monetary ASC) AS m_score
FROM customer_rfm;
```

## 3. Date Functions (`JULIANDAY`, `STRFTIME`)
**Where it was used:** `sql/02_rfm_analysis.sql` and `sql/01_exploration.sql`
**Why it was used:** SQLite lacks a built-in `DATEDIFF` function. `JULIANDAY` converts dates into integers to calculate the exact number of days between purchases. `STRFTIME` extracts the Year-Month string.
**Business Question:** *"Exactly how many days has it been since a customer's last purchase? Are there macro-seasonal trends?"*
**Implementation Example:**
```sql
-- Calculating exact days of Recency decay
CAST(JULIANDAY((SELECT snapshot_date FROM snapshot)) - JULIANDAY(MAX(s.invoicedate)) AS INTEGER) AS recency_days
```

## 4. Aggregate Functions (`SUM`, `MAX`, `AVG`)
**Where it was used:** Every SQL script.
**Why it was used:** To compress granular line-item transaction data into macro business metrics.
**Business Question:** *"How much total lifetime revenue has a customer generated?"*
**Implementation Example:**
```sql
ROUND(SUM(s.totalamount), 2) AS monetary
```

## 5. `COUNT(DISTINCT)`
**Where it was used:** `sql/01_exploration.sql` and `sql/02_rfm_analysis.sql`
**Why it was used:** To prevent massive data inflation. A single retail invoice often contains 50 different line items. Using a standard `COUNT(*)` would say the customer shopped 50 times. `COUNT(DISTINCT invoiceno)` correctly collapses it to 1 shopping trip.
**Business Question:** *"How many unique times did this customer actually visit the store and checkout?"*
**Implementation Example:**
```sql
COUNT(DISTINCT s.invoiceno) AS frequency
```

## 6. `GROUP BY`
**Where it was used:** `sql/01_exploration.sql` and `sql/02_rfm_analysis.sql`
**Why it was used:** To change the dimensionality of the dataset from "transaction-level" (one row per item) to "customer-level" or "country-level" (one row per entity).
**Business Question:** *"What is the total value of each specific country?"*
**Implementation Example:**
```sql
SELECT country, ROUND(SUM(totalamount), 2) AS total_revenue
FROM sales
GROUP BY country;
```

## 7. Subqueries
**Where it was used:** `sql/02_rfm_analysis.sql` (inside the `JULIANDAY` calculation)
**Why it was used:** To inject a scalar value (the dynamic snapshot date) directly into a row-level calculation without needing a complex `JOIN`.
**Business Question:** *"How do we compare each customer's last purchase date against the global dataset maximum?"*
**Implementation Example:**
```sql
JULIANDAY((SELECT snapshot_date FROM snapshot)) - JULIANDAY(MAX(s.invoicedate))
```

## 8. `CROSS JOIN`
**Where it was used:** `sql/03_segment_summary.sql`
**Why it was used:** To append the absolute Grand Total (Revenue and Customers) to every single Segment row, allowing us to calculate percentage shares.
**Business Question:** *"What exact percentage of our total corporate revenue is generated by the 'Champions' segment?"*
**Implementation Example:**
```sql
FROM customer_rfm s
CROSS JOIN totals t -- Joins the single-row Grand Total CTE to every Segment row
```

## 9. `WHERE` (Metadata Context)
**Where it was used:** `tests/test_data_quality.py`
**Why it was used:** While actual data filtering (removing cancellations/negative quantities) was handled in Pandas for superior error logging, SQL `WHERE` clauses were utilized in the Pytest suite to validate the existence of the SQLite metadata tables.
**Business Question:** *"Has the automated pipeline successfully instantiated the database schemas?"*
**Implementation Example:**
```sql
SELECT name FROM sqlite_master WHERE type='table' AND name='sales';
```

---
*Note: SQL concepts like `HAVING` and `CASE` were intentionally not used in the final repository. Operations typically handled by `HAVING` were executed as downstream boolean masks in Pandas, and `CASE WHEN` logic for segment naming was replaced with Pandas dictionary mapping for cleaner string management.*
